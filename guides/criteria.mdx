> Agents: the full documentation index is at [/llms.txt](https://docs.revcenter.ai/llms.txt).

A search runs the criteria you send. Each field either **filters** (narrows who is listed, before anyone is
read) or **scores** (ranks people once their profiles are read). `GET /v1/reference/criteria`
(MCP `get_criteria_reference`) returns every field with its allowed values; the launch's
`review.changes` says what Revcenter corrected and `review.warnings` what to check. The easiest way to get
criteria right is `POST /v1/criteria/draft` (`draft_criteria`): Revcenter's own reading of a job description, as
the app drafts a search.

## The minimum

`title_variants` (the role and its closest synonyms) and a place: `metro` with `geo_radius_mi`, `allowed_metros`, or
`remote_ok: true`. A search with no place is refused with `400 location_required`. For a role at a named site, send
that city and a radius, never a state or a country.

## The app's words

| In the app | In criteria |
| --- | --- |
| **Must match** | `flag: "must"` on `employers` or `degree_country`; `enforcement: "hard"` on `years_experience`; any filter field (`title_variants`, `metro`, `seniority`, `current_industries`…); `must_have` terms |
| **Ranks higher** | `flag: "prefer"`; `enforcement: "preferred"`; `preferred_employers`, `skills`, `keywords`, `must_have_context` |
| **Left out** | `flag: "exclude"`; `exclude_titles`, `exclude_companies`, `exclude_industries`, `exclude_functions`, `exclude_schools`, `exclude_locations` |
| **Suggested** | A value Revcenter added that the request didn't state (a level, an industry, a skill). A drafted filter is Must match or Left out only when the request's own words name it (the role's titles and its place aside), so a Suggested value only ranks; `draft_criteria` lists each filter with its `why`. Make it Must match, change it, or remove it. |

## Fields

{/* generated:criteria-fields (node scripts/docs/build-tables.mjs; do not edit by hand) */}
| Field | Filters or scores | What it is |
| --- | --- | --- |
| `title_variants` | Filters | Current job titles, literal, OR'd. The first is the role; it and its closest synonyms are sent (5 at most). Optional when an employer is a current must. |
| `seniority` | Filters | The level, sent with one level either side. |
| `allowed_seniority` | Filters | Levels to accept, instead of seniority's one either side. |
| `search_titles` | Filters | The exact titles to send instead of title_variants (at most 10), when the person edited the list. |
| `title_requires` | Filters | A title rule as groups that must all appear in the current title, any phrase per group: [["data center"], ["manager", "director"]] reads "data center" AND (manager OR director). |
| `title_boolean` | Filters | The title rule as written, at most 400 characters: AND, OR, NOT in capitals, brackets, "quoted phrases". |
| `keyword_boolean` | Filters | A keyword rule over the whole profile, as written: AND, OR, NOT in capitals, brackets, "quoted phrases"; at most 245 characters and 12 phrases, no commas. |
| `metro` | Filters | The role's own place: 'City, ST', a state or a country. |
| `allowed_metros` | Filters | More places, OR'd with metro. |
| `exclude_titles` | Filters | Current titles to leave out, sent as a filter before any profile is bought. A title that often shares one title with the role (Partner beside Principal) is not filtered: those people rank lower instead. |
| `exclude_industries` | Filters | Current employer industries to leave out (LinkedIn industry names). |
| `exclude_companies` | Filters | Current employers to leave out. |
| `years_experience` | Filters | \{min, max, ideal, basis: total\|relevant, enforcement: hard\|preferred\}. Hard bands are sent; preferred only ranks. |
| `employers` | Filters | Named employers: \{name, temporal: current\|past\|either, flag: must\|prefer\|exclude\}. must and exclude filter; prefer only ranks. |
| `past_titles` | Filters | Titles held before the current one. |
| `company_headcount` | Filters | Current employer size bands, A (self-employed) to I (10,001+). |
| `recently_changed_jobs` | Filters | Only people who changed jobs in the last 90 days. |
| `current_industries` | Filters | Industries the current employer must be in (LinkedIn names, search_industries). |
| `functions` | Filters | LinkedIn job functions to include. |
| `exclude_functions` | Filters | LinkedIn job functions to leave out. |
| `years_at_current_company` | Filters | \{min, max\} years at the current employer. |
| `schools` | Filters | Schools attended, by name. |
| `exclude_schools` | Filters | Schools to leave out. |
| `profile_languages` | Filters | The language the profile is written in, not a spoken language. |
| `exclude_locations` | Filters | Places candidates must not be in. |
| `company_hq_locations` | Filters | Where a candidate's current employer is headquartered ("Michigan", "Denmark"). |
| `must_have` | Scores | Short literal terms a profile must show, matched as text: at most 5 terms of at most 6 words each, like "CPA" or "PE license". Prose goes in must_have_context. |
| `must_have_context` | Scores | Requirements as prose, at most 10 items: context for screening, never matched as text. |
| `location_anchor_zips` | Scores | 5-digit ZIP codes the radius is measured from, at most 25. |
| `geo_radius_mi` | Scores | Commute radius around metro, in miles. |
| `remote_ok` | Scores | True when the role is remote: location then doesn't gate. |
| `skills` | Scores | Skills that rank. |
| `skills_required` | Scores | Hard skills; 'A or B' matches either. |
| `languages_required` | Scores | Spoken languages the role needs. |
| `signal_options` | Scores | Optional signals; needs_sponsorship true when the role can't sponsor a visa. |
| `shortlist_min_score` | Scores | The shortlist cut-off (default 80); a scoring change takes 50 to 85. |
| `preferred_employers` | Scores | Employers that rank up (current +8, past +5); never a gate. |
| `keywords` | Scores | Words anywhere on the profile, scored after reading; to filter by words before reading, use keyword_boolean. |
| `degree_country` | Scores | Where a degree is from, by the school's LinkedIn id, only when asked: countries (ISO codes), level, flag must or prefer. Unknown is not verified, never a match or a failure. See GET /reference/criteria. |
{/* end generated */}

Weights (`rubric_weights`) are a workspace setting an admin changes in **Settings → Scoring**; a search or scoring
change that sends them is refused with `400 weights_in_settings`. A few older fields are still accepted for
existing integrations and are left out of this table: `GET /v1/reference/criteria` lists the current set.

## Example

```json
{
  "title_variants": ["Tax Manager", "Senior Tax Manager"],
  "metro": "Dallas, TX",
  "geo_radius_mi": 30,
  "seniority": "manager",
  "years_experience": { "min": 7, "enforcement": "hard" },
  "employers": [
    { "name": "Deloitte", "temporal": "past", "flag": "prefer" },
    { "name": "PwC", "temporal": "past", "flag": "prefer" },
    { "name": "EY", "temporal": "past", "flag": "prefer" },
    { "name": "KPMG", "temporal": "past", "flag": "prefer" }
  ],
  "exclude_industries": ["Staffing and Recruiting"],
  "must_have": ["CPA"],
  "must_have_context": ["Partnership and corporate tax compliance for mid-market clients"]
}
```

`must_have` takes short literal terms a profile would contain (at most 5, each at most 6 words); a sentence
there is moved to `must_have_context`, which is scored, not matched as text.

> Agents: the full documentation index is at [/llms.txt](https://docs.revcenter.ai/llms.txt).

Launching a search and expanding return `202` with a `search_id` right away. The work runs in the background,
usually for a few minutes.

Poll `GET /v1/searches/{search_id}` every 30 seconds (a search takes minutes) until `status` is no longer `queued` or `running`.
The CLI (`revcenter status <id> --wait`) and MCP (`wait_for_search`) poll for you. While a search is `queued`,
`queue` has its place in line and `eta_seconds`, about when it starts; the CLI and MCP check less often the
further back it waits.

## Many searches at once

Launch as many as you have credits for, from as many agents as you like: none is refused for being busy. Past the
platform's limit a search waits its turn and starts as one finishes, and workspaces take turns. Before a big batch,
`GET /v1/capacity` (MCP `get_capacity`, CLI `revcenter capacity`) gives searches running and waiting, the platform's
pace, and `new_search.starts_in_seconds`, so you can tell the person when to expect results.

| `status` | Meaning | Done? |
| --- | --- | --- |
| `queued` | Waiting to start | No |
| `running` | Working; `stage` says where | No |
| `stalled` | No activity for 3 minutes | Stop waiting; check later |
| `complete` | Finished; `outcome` and `delivered` are set | Yes |
| `failed` | Stopped by an error. A launch that fails to start gives its credit back | Yes |
| `stopped` | Stopped early; `stop_reason` says why | Yes |

Treat an unknown status as done. Don't branch on `stage` or `stop_reason`.

```json
{
  "id": "…",
  "status": "complete",
  "stage": null,
  "stop_reason": "target_reached",
  "outcome": "Shortlist ready",
  "profiles_read": 214,
  "delivered": 12,
  "database_only": false,
  "expansion": false
}
```

`outcome` is `Shortlist ready` (6+ delivered), `Poor yield` (1 to 5) or `No results` (0).

While a search on a project runs, expanding the project or applying scoring changes returns `409 search_running`.

> Agents: the full documentation index is at [/llms.txt](https://docs.revcenter.ai/llms.txt).

| Limit | Default |
| --- | --- |
| Requests per key | 600 a minute |
| Requests per workspace | 3,000 a minute |
| Launching a search or an expansion | Not counted |
| Searches running at once | No limit per workspace; past the platform's, they wait their turn |
| Active keys | 5 |

There is no daily cap: how many searches you run is set by your [credits](/guides/billing). Your
limits and today's use are in **Settings → Usage → API** and `GET /v1/me`.

## Headers

Every authenticated response carries:

| Header | Meaning |
| --- | --- |
| `x-ratelimit-limit` | Requests allowed this minute |
| `x-ratelimit-remaining` | Requests left this minute |
| `x-ratelimit-reset` | When the minute resets (Unix seconds) |

## 429

A `429` has a `Retry-After` header and the same number in `error.details.retry_after_seconds`.

| Code | Means | `Retry-After` |
| --- | --- | --- |
| `rate_limited` | Too many requests this minute | Until the minute resets |
| `launch_in_progress` | The same `Idempotency-Key` is still being started by another request | 5 |

A launch is never refused for being busy. A paid launch (`launch_search`, `expand_search`) is not counted
against the request limits: each one reserves credits, and a search past the platform's limit waits its
turn with `status: queued` and a `queue.eta_seconds`. Workspaces take turns, so many searches waiting in one
workspace don't hold up another workspace's first one. `GET /v1/capacity` says how busy it is and when a search
launched now would start. A database-only launch uses no credits and is counted like any request.

A `429` means nothing ran and no credits were reserved. The CLI and MCP server wait out `Retry-After` and retry for
you, with the same `Idempotency-Key`, for up to three minutes (`REVCENTER_RETRY_SECONDS` changes it).

Behind the API, every running search's LinkedIn reads share one pool fairly: the search holding the fewest
reads goes next, so a workspace alone can use all of it and a busy one never starves another.

> Agents: the full documentation index is at [/llms.txt](https://docs.revcenter.ai/llms.txt).

Exports are free and nothing in them is cut off. Use CSV for a spreadsheet and JSON Lines for an agent: JSON Lines
is lossless.

## What you can export

| You want | API | MCP |
| --- | --- | --- |
| The project's shortlist | `/projects/{id}/shortlist.csv` | `export_shortlist` |
| Everyone one search returned, read or not | `/searches/{id}/records.csv` | `export_search_records` |
| Everyone a project's searches returned | `/projects/{id}/records.csv` | `export_project_records` |
| The workspace's candidate database | `/candidates.csv` | `export_candidates` |
| A version published to the client | `/projects/{id}/shortlist/versions/{versionId}.csv` | `export_shortlist_version` |

The same lists page as JSON without `.csv`: `GET /searches/{id}/records`, `GET /projects/{id}/records`,
`GET /candidates`, `GET /projects/{id}/shortlist`. Each record has a `status`:

| `status` | Meaning | `score` | `profile` |
| --- | --- | --- | --- |
| `scored` | Read and scored by this search | Its score | The read profile |
| `known` | Already in your workspace from another search | `null` | The profile on file |
| `not_read` | Listed, never read | `null` | `null` |

A project's records hold one record per person across all its searches: `scored` by any search beats `known`,
which beats `not_read`, `score` is the best any gave, `first_search_id` is the search that listed them first and
`search_ids` every search that returned them (joined by `;` in a CSV).

## Formats

| Format | Ask for it | What you get |
| --- | --- | --- |
| CSV | the default (`format=csv`) | One row per person, UTF-8 with a byte order mark so Excel shows "·" and "–" as written. A cell a spreadsheet would run as a formula is written as text. `columns` picks the columns, in the order you list them. |
| JSON Lines | `format=jsonl` (MCP `format: "jsonl"`) | One JSON object per line: the list call's fields plus the groups below and the whole read `profile`. `fields` keeps only the groups you list. |

## Columns

`GET /v1/reference/export-columns` (MCP `get_export_columns`) lists them. Send keys as
`columns=name,title,company,roles,score`; a key that isn't a column is refused with `400 invalid_columns`, naming it.

`roles` and `schools` stand for numbered columns, one block for every role (current role first) and every school
(listed under the table). A file has as many as the most anyone in it has; one numbered column can be named on its
own (`experience_3_company`). Dates are `YYYY-MM` (`YYYY` when the profile gives only a year), and a role
still held ends `present`.

The team's own notes and reasons on a decision stay in Revcenter; the client's feedback is included. A profile
holds only what was read: one read in its short form has fewer roles and skills than the person's full page.

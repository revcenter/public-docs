> Agents: the full documentation index is at [/llms.txt](https://docs.revcenter.ai/llms.txt).

Every error has one shape. Branch on `error.code`; the message can change.

```json
{
  "error": {
    "code": "invalid_criteria",
    "message": "title_variants: Required",
    "details": { "issues": [{ "field": "title_variants", "message": "Required" }] },
    "request_id": "6f1c2b7e-9a3d-4c5f-8e21-0b7d4a9c1e33"
  },
  "meta": { "request_id": "6f1c2b7e-9a3d-4c5f-8e21-0b7d4a9c1e33" }
}
```

`details` is often `null`. Quote `request_id` when you contact support.

## Codes

| Status | Code | Meaning | What to do |
| --- | --- | --- | --- |
| `400` | `invalid_criteria` | Criteria failed validation | Fix the fields named; see `GET /v1/reference/criteria` |
| `400` | `criteria_required` | No `criteria` and no `jd_text` of 40+ characters | Send one |
| `400` | `location_required` | The criteria name no place and don't set `remote_ok` (on a launch, its preview, or `draft_criteria`); nothing was reserved | Set `metro` to the role's city or state with `geo_radius_mi`, or `allowed_metros` for several places, or `remote_ok: true` for a remote role |
| `400` | `idempotency_key_required` | A launch without an `Idempotency-Key` (8 to 160 characters) | Add the header |
| `400` | `max_credits_too_low` | `max_credits` is under 250, too small to buy one page of results and read its profiles (`details.minimum` is 250) | Send 250 or more: the amount the person names, up to the workspace's most per search, or leave it out for that most |
| `400` | `invalid_max_credits` | `max_credits` is not a whole number from 250 to 20,000 | Send the amount the person names as a whole number, or leave it out for the workspace's most per search |
| `400` | `invalid_format` | An export's `format` is not `csv` or `jsonl` | Leave it out for CSV, or send `format=jsonl` |
| `400` | `needs_new_search` | A scoring change tried to change titles or places | Launch a new search |
| `400` | `weights_in_settings` | A scoring change sent `rubric_weights`: weights are a workspace setting | Ask a workspace admin to change them in Settings, Scoring |
| `400` | `candidate_ids_required` | Adding to a shortlist without `candidate_ids` | Send the ids |
| `400` | `invalid_name` | Project name empty or over 120 characters | Fix the name |
| `400` | `invalid_cursor` | A cursor this API didn't return | Start without it |
| `400` | `invalid_fields` · `invalid_view` | A list's `fields` names a profile slice that doesn't exist, or `get_search`'s `view` is not `full` or `status` | Use the slices the message lists; leave `view` out or send `status` |
| `400` | `not_proposable` | This action can't be previewed | Call it directly |
| `400` | `invalid_proposal` | A `proposal_id` that is altered or not for this key | Preview again |
| `400` | `proposal_required` | `publish_shortlist` or `send_shortlist_email` called on its own route: it reaches the client, so it runs only from an applied proposal. Nothing was sent | Preview it with `preview_action`, show the person, then `apply_proposal` once they agree |
| `400` | `confirmation_required` | Deleting a project without its exact name as `confirm_name`; nothing was deleted | Send the name `get_project` returns, or archive it instead |
| `400` | `invalid_verdict` · `invalid_reason` · `invalid_dnc` · `invalid_project_update` · `invalid_expected_count` | A verdict, decline reason, do-not-contact entry, project change or expected count that isn't valid | Fix the field named in the message |
| `400` | `client_workspace_required` | No client workspace to email: `client_workspace_id` isn't a workspace id, or the project isn't assigned to a client portal | Send `client_workspace_id` |
| `400` | `top_up_amount_out_of_range` | A top-up outside $1,500 to $30,000 | Pick an amount in range |
| `400` | `invalid_webhook_url` · `invalid_webhook_events` · `invalid_webhook` | A webhook URL that isn't public HTTPS (private, loopback and link-local addresses are refused), an unknown event type, or a bad `description` or `enabled` | Fix the field named; see [webhooks](/guides/webhooks) |
| `401` | `missing_api_key` | No `Authorization: Bearer` header | Send the key |
| `401` | `invalid_api_key` | Key invalid, expired or revoked | Use a current key |
| `400` | `member_api_search_cap` | `max_credits` is above the most your workspace's admins allow you per search through the API | Send a smaller `max_credits`, or ask an admin to raise it in **Settings → Integrations → API** |
| `402` | `plan_required` | No active plan | Choose a plan in **Settings → Plan & billing** |
| `402` | `no_active_plan` · `shortlist_allocation_exhausted` | No plan, or not enough credits for the search's `max_credits`. `details` has `billing_url` and `top_up` | A smaller `max_credits`, `revcenter topup`, or see [billing](/guides/billing) |
| `402` | `member_api_budget_reached` | Your monthly API budget, set by your workspace's admins, doesn't cover this search | A smaller `max_credits`, wait for the 1st (UTC), or ask an admin to raise it in **Settings → Integrations → API** |
| `403` | `admin_required` | Only a workspace admin can do this, and your key acts as you, an Editor | Ask an admin, or use an admin's key |
| `403` | `api_access_disabled` | API access is off for this workspace | Ask your Revcenter contact |
| `403` | `insufficient_scope` | The key can't make this call | Use a key from **Settings → Integrations → API** |
| `403` | `key_has_no_owner` | The action is recorded as a person, and this key has none behind it | Use a key from **Settings → Integrations → API** or `revcenter auth login` |
| `403` | `shortlist_email_in_testing` | Emailing shortlists is in testing for developer accounts | Send the client the share link (`get_share_link`) instead |
| `404` | `project_not_found` · `search_not_found` · `candidate_not_found` | No such id in this workspace | Check the id |
| `404` | `scoring_job_not_found` | No such scoring job on this search | Use the `job_id` `preview_scoring` or `apply_scoring` returned |
| `404` | `webhook_not_found` · `delivery_not_found` | No such webhook endpoint or delivery in this workspace | Check the id with `list_webhooks` |
| `404` | `shortlist_version_not_found` · `client_workspace_not_found` | No such published shortlist version on the project, or no such client workspace | Check the id with `list_shortlist_versions` or `preview_shortlist_email` |
| `409` | `idempotency_key_reused` | The `Idempotency-Key` was used for a different request | Use a new key |
| `409` | `search_running` | A search on the project is still running | Wait for it |
| `409` | `search_not_finished` · `no_search_to_expand` | The project can't be expanded now | Wait for its search, or launch one |
| `409` | `project_credit_limit` | The project's searches have used its credit limit (three searches' worth at the workspace's per-search limit) | Start a new project for a different role or place |
| `409` | `cannot_continue` | `expand_search` with `search_id` on a search that can't go on as it was (LinkedIn had no one left, or it failed on its criteria) | Call `expand_search` without `search_id`, or launch a new search with the criteria changed |
| `409` | `proposal_expired` | The proposal is over 30 minutes old | Preview again |
| `409` | `project_in_use` | The project has delivered work that keeps it; nothing was deleted | Archive it instead (`update_project` with `archived` true) |
| `409` | `shortlist_changed` | The shortlist holds a different number of people than the person was shown (`details` has `expected` and `actual`); nothing was sent | Preview again and show the person the new list |
| `409` | `empty_shortlist` · `shortlist_not_publishable` | Nothing on the shortlist to publish or send, or no one on it came from a search in the project | Add people, or run a search in the project first |
| `409` | `workspace_name_mismatch` | `confirm_workspace_name` isn't the client workspace's name; nothing was sent | Preview it again (`preview_shortlist_email`) and send the name it shows |
| `409` | `webhook_limit` · `webhook_disabled` | The workspace already has 10 webhook endpoints, or a redelivery to an endpoint that is turned off | Delete one; turn the endpoint on first |
| `413` | `response_too_large` | `get_shortlist` with `fields` would be more than one answer holds (about 100 KB); nothing was cut | Ask for fewer fields, or page through `list_people` with `fields` |
| `424` | `search_unavailable` | Live search is unavailable | Retry later, or use `database_only` |
| `429` | `member_rate_limited` | Your workspace's admins limit how many requests a minute you can make | Wait for `Retry-After`, or ask an admin to raise it in **Settings → Integrations → API** |
| `429` | `rate_limited` · `network_busy` · `launch_in_progress` | Too many requests, the network is briefly full (only with the search queue off), or the same Idempotency-Key is still being started; nothing ran | Wait for `Retry-After` (the CLI and MCP retry for you); see [rate limits](/guides/rate-limits) |
| `500` | `internal_error` | Something failed on our side | Retry with backoff |
| `503` | `access_check_unavailable` · `plan_check_unavailable` | Access or plan couldn't be checked; nothing ran | Retry after `Retry-After` |
| `503` | `busy` | Revcenter is busy. A read or preview changed nothing; `details` has `retry_after_seconds` | Retry after `Retry-After` |
| `503` | `top_up_unavailable` | Top-ups can't be started here | Use **Settings → Plan & billing** |

A top-up can also answer `409 top_up_needs_plan` (top-ups use a plan's rate; choose a plan first), with
`details.billing_url`.

The browser login has its own codes (`authorization_pending`, `slow_down`, `access_denied`, `expired_token`,
`invalid_grant`); see [authentication](/authentication#browser-login-api).

## CLI and MCP

The CLI prints the code, a one-line fix and the `request_id` on standard error, and exits with a
[code](/concepts/cli-basics#exit-codes) by kind. The MCP server returns the same lines as an error result.

```text
revcenter: project_not_found: No project with that id in this workspace.
  fix: Check the id with list_projects; ids belong to one workspace.
  request_id: 6f1c2b7e-9a3d-4c5f-8e21-0b7d4a9c1e33
```

## Safe to retry

| Request | Retry? |
| --- | --- |
| Any `GET`, previews, `POST /actions/preview` | Yes |
| `POST /projects/{id}/searches` | Yes, with the **same `Idempotency-Key`**: same search, never charged twice |
| Scoring apply, database pass, shortlist add and remove, cancel | Yes |
| `POST /proposals/apply` | Yes for a search launch; otherwise as the action itself |
| `POST /projects` | No: each call makes a project |
| `POST /projects/{id}/expand` | No: each success reserves credits. Check `GET /projects/{id}/searches` first |

Retry `429` after `Retry-After` and `5xx` with backoff. Fix other `4xx` before retrying.

### Idempotency keys

An `Idempotency-Key` (8 to 160 printable characters) belongs to the workspace and is kept for good. A later launch
with the same key:

| Same project and body | Different project or body |
| --- | --- |
| `200` with the first search and `"reused": true`; no second credit | `409 idempotency_key_reused`; nothing runs |

Name the key after one piece of work, such as `nightly-<requisition id>`.

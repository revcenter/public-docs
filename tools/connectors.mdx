Revcenter runs a hosted MCP server. Add it to your AI app as a custom connector and the app can draft
criteria, run searches and read shortlists in your workspace, with nothing to install.

```text
https://api.revcenter.ai/mcp
```

When you add it, the app sends you to Revcenter to sign in. Pick the workspace to connect and click
**Authorize**. Any member, Admin or Editor, connects apps, and the workspace needs a plan or credits. The app acts
as you, with your role: an Editor's connection sees only their own projects.

## Add it to your app

<Tabs>
  <Tab title="Claude">
    1. Open **Customize → Connectors**, click **+ Add** and choose **Add custom connector**. On Team and
       Enterprise, an owner adds it first under **Organization settings → Connectors** (**Add → Custom → Web**),
       then members click **Connect**.
    2. Name it Revcenter, paste the URL and click **Continue**. Keep the detected sign-in settings and click
       **Add**.
    3. Click **Connect**, sign in to Revcenter and pick the workspace.

    Works in Claude on the web, desktop and mobile. On the Free plan you can add one custom connector.
  </Tab>
  <Tab title="ChatGPT">
    1. In ChatGPT on the web, open **Plugins**, click **+** and choose **Add custom MCP server**. Account and
       workspace policies decide who can add one: on Business, Enterprise and Edu, a workspace admin turns on
       developer mode first (**Workspace settings → Permissions & roles**).
    2. Name it Revcenter, paste the URL under **Connection** and choose **OAuth** for authentication.
    3. Accept the warning, select **Create as a plugin**, then sign in to Revcenter when asked and pick the
       workspace.
  </Tab>
</Tabs>

Any other MCP client that speaks Streamable HTTP and OAuth can connect the same way. A client that can't sign
in through a browser uses an API key instead: see [Custom LLMs and agents](#custom-llms-and-agents).

## Custom LLMs and agents

Model APIs, IDEs and agent frameworks can't open a browser to sign in. Give them the same URL and a Revcenter
API key as a bearer token:

```text
URL:     https://api.revcenter.ai/mcp
Header:  Authorization: Bearer rvc_live_…
```

### Get an API key

Any member creates one under **Settings → Integrations → API** ([Authentication](/authentication)); it acts as them, with their role. A key made
there holds every agent scope (`projects`, `searches`, `shortlists` and `webhooks`, each `:read` and
`:write`), which is what the tools need. A key with fewer scopes lists only the tools its scopes reach, and a
call beyond them is refused with `insufficient_scope`, exactly as the [API](/api-reference/introduction) refuses it.

The key works at `/mcp` as it does at `/v1`: the same plan rule (`plan_required` without a plan or credits),
rate limits, expiry and revocation, and its tool calls appear in the workspace's API logs under the key's
name. Send it only in the `Authorization` header; a key in the URL is never read. Keep it in an environment
variable or secret store, never in code or a prompt.

### OpenAI Responses API

The `mcp` tool sends `authorization` to the server as the bearer token.

<CodeGroup>
```bash curl
curl https://api.openai.com/v1/responses \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -d '{
    "model": "gpt-6-astra",
    "tools": [{
      "type": "mcp",
      "server_label": "revcenter",
      "server_url": "https://api.revcenter.ai/mcp",
      "authorization": "'"$REVCENTER_API_KEY"'",
      "require_approval": "never"
    }],
    "input": "List my Revcenter projects."
  }'
```

```python Python
import os
from openai import OpenAI

client = OpenAI()
response = client.responses.create(
    model="gpt-6-astra",
    tools=[{
        "type": "mcp",
        "server_label": "revcenter",
        "server_url": "https://api.revcenter.ai/mcp",
        "authorization": os.environ["REVCENTER_API_KEY"],
        "require_approval": "never",
    }],
    input="List my Revcenter projects.",
)
print(response.output_text)
```
</CodeGroup>

### Anthropic Messages API

The MCP connector is in beta: send the `anthropic-beta: mcp-client-2025-11-20` header (or `betas` in the SDK),
name the server in `mcp_servers` with the key as `authorization_token`, and enable its tools with an
`mcp_toolset` entry.

<CodeGroup>
```bash curl
curl https://api.anthropic.com/v1/messages \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $ANTHROPIC_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "anthropic-beta: mcp-client-2025-11-20" \
  -d '{
    "model": "claude-opus-5-5",
    "max_tokens": 2000,
    "messages": [{"role": "user", "content": "List my Revcenter projects."}],
    "mcp_servers": [{
      "type": "url",
      "url": "https://api.revcenter.ai/mcp",
      "name": "revcenter",
      "authorization_token": "'"$REVCENTER_API_KEY"'"
    }],
    "tools": [{"type": "mcp_toolset", "mcp_server_name": "revcenter"}]
  }'
```

```python Python
import os
import anthropic

client = anthropic.Anthropic()
response = client.beta.messages.create(
    model="claude-opus-5-5",
    max_tokens=2000,
    messages=[{"role": "user", "content": "List my Revcenter projects."}],
    mcp_servers=[{
        "type": "url",
        "url": "https://api.revcenter.ai/mcp",
        "name": "revcenter",
        "authorization_token": os.environ["REVCENTER_API_KEY"],
    }],
    tools=[{"type": "mcp_toolset", "mcp_server_name": "revcenter"}],
    betas=["mcp-client-2025-11-20"],
)
print(response.content)
```
</CodeGroup>

```json Cursor (~/.cursor/mcp.json)
  }

```

Cursor reads `${env:REVCENTER_API_KEY}` from your shell environment; VS Code asks for the key once and stores
it.

### Any other MCP client

Windsurf, LangChain's MCP adapters and any other client that speaks MCP over Streamable HTTP connect the same
way: the URL, transport `streamable_http` (or `http`), and the header `Authorization: Bearer <key>`. The
server is stateless: POST JSON-RPC and each request is answered on its own, as JSON; there is no session id
and no GET stream.

Your agent runs each tool when it calls it. A launch spends credits, so have it confirm the criteria and
the cap with a person first.

## What it can do

A chat gets the tools for work done in a conversation, named for what they do. File exports, webhooks, raw
result records and published-version history stay in the [API](/api-reference/introduction), the
[CLI](/tools/cli) and the [local MCP server](/tools/mcp).

| For | Tools |
| --- | --- |
| Account | `get_account`, `get_credits` (credits left, and the workspace's limit per search and prices) |
| Criteria | `draft_search_criteria`, `list_criteria_fields`, `find_industries` |
| Projects | `list_projects`, `create_project`, `get_project` |
| Searches | `launch_search`, `launch_searches`, `wait_for_search`, `get_search`, `list_searches`, `find_more_candidates`, `cancel_search` |
| Results | `list_search_candidates`, `preview_scoring_change`, `apply_scoring_change`, `wait_for_scoring_change`, `get_shortlist_summary` |
| Shortlist | `get_shortlist`, `add_to_shortlist`, `remove_from_shortlist` |
| Decisions | `record_candidate_decision`, `get_candidate_decisions`, `list_decision_reasons` |
| Do not contact | `list_do_not_contact`, `add_to_do_not_contact` |
| Client | `get_client_share_link`, `preview_client_email`, `send_client_email`, `list_client_feedback` |
| Candidate database | `search_candidate_database` |

The app asks you before any tool that changes something: a launch (it uses credits), a shortlist change (the
client's link shows it) or an email to the client. Reads run without asking. A decision you record is private
to your team and doesn't change the shortlist. Repeating a launch returns the same search and never pays twice.
Projects are archived from a chat, never deleted: deleting one is done in the app.

Searches take minutes. Ask the app to wait for the search (`wait_for_search` waits up to three minutes a
call), then to list everyone scoring 80 or more.

## Disconnect

**Settings → Integrations → Connectors** lists the connected apps. **Revoke** stops one at once. Each connection is
also an API key in **Settings → Integrations → API**, named after the app; revoking it there does the same.
Connecting the same app again replaces its earlier connection. Connections never count toward the workspace's
limit on API keys, so connecting is never refused for it.

## Security

- Sign-in uses OAuth 2.1 with PKCE. The app never sees your password or an API key. Custom LLMs and agents
  use an API key you give them instead; revoke it in **Settings → Integrations → API** to cut them off.
- An access token lasts an hour and works only at `https://api.revcenter.ai/mcp`, for the one workspace you
  picked. The app renews it with a refresh token that changes on every use; a refresh token used twice
  disconnects the app.
- Every call runs through the Revcenter API as that connection: the same permissions, plan, credits and
  rate limits as an API key.

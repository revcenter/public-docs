> Agents: the full documentation index is at [/llms.txt](https://docs.revcenter.ai/llms.txt).

```bash
curl -fsSL https://revcenter.ai/install.sh | sh   # or: npm install -g revcenter
revcenter auth login                              # authorize in your browser
revcenter projects --pretty
```

Needs Node 22 or later. The installer uses your global npm folder when it can write to it, and `~/.revcenter`
(added to your PATH) when it can't, so it never needs sudo. Set `REVCENTER_VERSION` to pin a version and
`REVCENTER_NO_LOGIN=1` to skip the sign-in prompt. `rvc` is a short alias.

## Signing in

`revcenter auth login` opens your browser and waits for you to pick a workspace and authorize. Over SSH, or
with `--no-browser`, it prints a link and a code to open anywhere. Any member, Admin or Editor, can sign in. The
CLI then holds its own tokens for this computer, kept in its keychain and never printed; they renew themselves
and act as you, with your role ([How the CLI stays signed in](/authentication#how-the-cli-stays-signed-in)).

| Option | Use when |
| --- | --- |
| `--no-browser` | The machine has no browser: open the printed link anywhere. |
| `--start`, then `--finish` | An agent runs the login: `--start` prints the link and exits, `--finish` waits for approval. |
| `--key <key>` or `--key -` | You already have a key from **Settings → Integrations → API**, passed or piped on standard input. |

`revcenter auth status` shows the workspace, this computer's name and where the sign-in is kept.
`revcenter auth logout` signs this computer out on the server and removes the tokens.

The CLI uses `REVCENTER_API_KEY` when set, otherwise this computer's sign-in (or a key saved with `--key`, or by
an older CLI).

| Variable | Meaning | Default |
| --- | --- | --- |
| `REVCENTER_API_KEY` | The API key | this computer's sign-in |
| `REVCENTER_API_URL` | The API's address | `https://api.revcenter.ai` |
| `REVCENTER_CONFIG_DIR` | Where the sign-in is described | `~/.config/revcenter` (or `$XDG_CONFIG_HOME/revcenter`) |
| `REVCENTER_CREDENTIAL_STORE` | `file` keeps the tokens in `credentials.json` instead of the keychain; `keychain` refuses that fallback | the keychain, else the file |
| `REVCENTER_TIMEOUT_SECONDS` | How long one request may take | `90` (`300` for an export) |
| `REVCENTER_RETRY_SECONDS` | How long to keep retrying what is safe to retry; `0` turns retries off | `180` |
| `REVCENTER_NO_UPDATE_CHECK` | `1`: no daily check for a newer release. The check runs only at a terminal, never in CI, scripts or the MCP server, and never delays a command | unset |

`credentials.json`, readable by you only (mode `600`), says which workspace and computer; the tokens are in the
keychain unless there is none. A sign-in is checked against the API before the CLI reports it.

## Output

- Results are **JSON on standard output**; lists are `{ "data": [...], "cursor": ... }`. Use JSON in scripts.
- `--pretty` prints tables instead.
- Exports: `--csv` for a spreadsheet (`--columns name,title,roles` picks the columns; `revcenter columns` lists them),
  `--jsonl` for JSON Lines (`--fields person,career` picks the groups). See the [Exports reference](/guides/exports).
- Progress and warnings go to **standard error**. When the API needs a newer CLI, standard error says so once.
- `revcenter --help` lists commands, `revcenter help <command>` shows examples, and `--version` prints the version.
- Shell completions: `revcenter completion zsh > "${fpath[1]}/_revcenter"` (or `bash`, `fish`).

`search` takes `--key <key>`, an idempotency key: the same key returns the same search and never reserves twice.
Without one, a key is derived from the project and request, so repeating an identical command is safe.
`--target <n>` is how many people to aim for, 1 to 100.

## Exit codes

| Exit | Name | When |
| --- | --- | --- |
| `0` | `ok` | Succeeded. |
| `1` | `server` | The API failed or couldn't be reached. Retry with backoff. |
| `2` | `usage` | Bad command, flag or argument. Nothing was sent. |
| `3` | `auth` | No key, a bad key, or no access (`401`, `403`). |
| `4` | `not_found` | No such project, search or candidate (`404`). |
| `5` | `refused` | The API refused the request (`400`, `409`, other `4xx`). Fix it before retrying. |
| `6` | `rate_limited` | A rate or capacity limit (`429`). Wait, then retry. |
| `7` | `payment` | No plan, or not enough credits for the search's cap (`402`). |
| `8` | `missing_tool` | A program the command runs isn't installed (`revcenter code` needs Claude Code). |

Every request has a timeout (`REVCENTER_TIMEOUT_SECONDS`: 90 by default, 300 for an export). A `429` is waited
out and retried, as told by `Retry-After`; a `5xx`, a timeout or a dropped connection is retried with backoff only
when repeating it can't do anything twice: a read, a preview, or a launch, expansion, scoring change or verdict,
which carry an idempotency key. Retries stop after `REVCENTER_RETRY_SECONDS` (180; `0` turns them off), and each
wait is said on standard error. `revcenter doctor` checks the sign-in, the API and the version.

## Errors

Errors go to standard error with the code, a one-line fix and the `request_id`:

```text
revcenter: project_not_found: No project with that id in this workspace.
  fix: Check the id with list_projects; ids belong to one workspace.
  request_id: 6f1c2b7e-9a3d-4c5f-8e21-0b7d4a9c1e33
```

Codes are the [API's error codes](/api-reference/introduction#errors), plus the CLI's own:

| Code | When | Exit |
| --- | --- | --- |
| `missing_api_key` | No key in the environment or saved | `3` |
| `invalid_key` | `auth login --key` got something that isn't a Revcenter key | `3` |
| `invalid_argument` | A missing or malformed argument, or an unreadable file | `2` |
| `unknown_command` | No such command | `2` |
| `network_error` | The API couldn't be reached (refused, reset) | `1` |
| `dns_error` | The API's address couldn't be found: offline, or a wrong `REVCENTER_API_URL` | `1` |
| `tls_error` | The secure connection failed (often a proxy that intercepts HTTPS: set `NODE_EXTRA_CA_CERTS`) | `1` |
| `timeout` | No answer in time. It may still have run: reads and launches are safe to repeat | `1` |
| `invalid_response` | Something other than the API answered (a proxy or captive portal) | `1` |
| `unknown_action` | `revcenter call` got a name that isn't in `revcenter actions` | `2` |

> Agents: the full documentation index is at [/llms.txt](https://docs.revcenter.ai/llms.txt).

Your agent does the reasoning; Revcenter searches, scores and keeps the shortlist. There are two servers:

| Server | Where | Signs in with | Tools |
| --- | --- | --- | --- |
| **Hosted** (`https://api.revcenter.ai/mcp`) | Claude and ChatGPT ([setup](/tools/connectors)), coding agents, model APIs, IDEs | OAuth, or an API key as a bearer token | The chat tools: drafting, searches, results, shortlist, decisions, do-not-contact, the client link and email |
| **Local** (`npx -y revcenter mcp`) | Claude Code, Codex, Cursor, Gemini CLI, Claude Desktop | An API key in `REVCENTER_API_KEY` | Every tool below, plus exports to files |

## Connect a coding agent

The hosted server needs nothing installed. Add it by URL and sign in once in your browser:

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add -s user --transport http revcenter https://api.revcenter.ai/mcp
    ```
  </Tab>
  <Tab title="Others">
    Add a remote (Streamable HTTP) MCP server with the URL `https://api.revcenter.ai/mcp`. Clients that support
    MCP sign-in open your browser to authorize; the others send an API key, as below.
  </Tab>
</Tabs>

For every tool, including exports saved as files, run the local server. It reads an API key from **Settings →
Integrations → API** ([Authentication](/authentication)) in `REVCENTER_API_KEY`:

```json
{ "mcpServers": { "revcenter": { "command": "npx", "args": ["-y", "revcenter", "mcp"], "env": { "REVCENTER_API_KEY": "rvc_live_…" } } } }
```

Keep the key out of prompts and shared files: where your client can read it from the environment or a secret
store, put it there. Restart the client and ask it to "list my Revcenter projects".

## Your own LLM or agent

Model APIs, IDEs and agent frameworks that can't sign in through a browser use the hosted server with an API key
(**Settings → Integrations → API**, [Authentication](/authentication)) as a bearer token:

```text
URL:     https://api.revcenter.ai/mcp
Header:  Authorization: Bearer rvc_live_…
```

Transport is Streamable HTTP (`streamable_http` or `http`). The server is stateless: each JSON-RPC POST is
answered on its own. A key with fewer scopes lists only the tools its scopes reach. Send the key only in the
header, from an environment variable or secret store, never in a prompt.

<CodeGroup>
```json Cursor (~/.cursor/mcp.json)
{
  "mcpServers": {
    "revcenter": {
      "url": "https://api.revcenter.ai/mcp",
      "headers": { "Authorization": "Bearer ${env:REVCENTER_API_KEY}" }
    }
  }
}
```

```json VS Code (.vscode/mcp.json)
{
  "inputs": [{ "type": "promptString", "id": "revcenter-key", "description": "Revcenter API key", "password": true }],
  "servers": {
    "revcenter": { "type": "http", "url": "https://api.revcenter.ai/mcp", "headers": { "Authorization": "Bearer ${input:revcenter-key}" } }
  }
}
```
</CodeGroup>

Model APIs that take a remote MCP server (an `mcp` tool or `mcp_servers` entry) need the same two things: the
URL, and the key as the server's authorization token. Your agent runs each tool when it calls it, so have it
confirm the criteria and the cap with a person before a launch.

## A starter prompt

```text
Use Revcenter. For each role below: draft criteria with draft_criteria from the job description, show me the
criteria and any review.warnings, and change only what I ask. Then launch all of them together with
launch_searches, wait for each with wait_for_search, read each search's advice, and list everyone scoring 80 or
more with name, title, company and place. Export each shortlist as CSV.
```

## Approvals

Nothing that spends credits or reaches the client runs without the person. On the hosted server your client asks
before any tool that isn't read-only. The local server asks itself:

1. The server previews the action: what it does, the most it reserves, and the credits left.
2. If the client can ask, it asks in one sentence with Accept and Decline: `Launch search "Associate · Paul Weiss
   · New York": reserves up to 5,000 credits, unused credits are refunded. 421,000 credits left.` Each review
   warning follows on its own line, starting `Check:`.
3. Otherwise, or after 10 minutes without an answer, the tool returns `status: "pending_approval"` with a
   `proposal`. Nothing has run. The agent shows it and calls `apply_proposal` once the person agrees. A
   proposal lasts 30 minutes.

Launches that arrive together (parallel sub-agents, or `launch_searches` with up to 25) are asked once, with
every search and the total listed. `publish_shortlist` and `send_shortlist_email` are asked the same way, in their
own words (who the client sees, where the email goes), and so are `add_dnc_from_search` and `add_dnc` with more
than 25 people. Called directly, those are refused with `proposal_required`.

A launch without its own `idempotency_key` gets one from the project and the request, so repeating an identical
launch (after a timeout, say) returns the first search and reserves nothing more. `max_credits` is any whole number
from 250, the smallest cap Revcenter takes, up to your workspace's limit per search.

## Many searches at once

Launch as many as you like; up to 3 run at once per workspace, and the rest queue (`status: queued`, with
`queue.eta_seconds`) and start in turn. Have one sub-agent per role, then merge: export tools save under
`./revcenter-exports/`, as CSV for a spreadsheet or JSON Lines (`format: "jsonl"`) for an agent to read. See the
[Exports reference](/guides/exports).

and on lists `cursor` and `total`; an error returns its [code](/api-reference/introduction#errors), a one-line
fix and the `request_id`.

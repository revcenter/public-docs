`revcenter mcp` runs a local MCP server. Your agent does the reasoning; Revcenter searches, scores and keeps the
shortlist.

## Connect

The quickest way: paste this into Claude Code, Codex, Cursor or any coding agent.

```text
Set up the Revcenter plugin by following the steps in https://github.com/revcenter/agent-plugins
```

The agent installs the CLI, signs you in (you click **Authorize** once in your browser), connects itself and
tells you how many credits you have. In Claude Code you can also install the plugin directly:

```text
/plugin marketplace add revcenter/agent-plugins
/plugin install revcenter@revcenter-plugins
```

Or do it yourself: install, sign in, and let the CLI add the server to every AI tool on the machine:

```bash
curl -fsSL https://revcenter.ai/install.sh | sh
revcenter login
revcenter setup        # Claude Code, Codex, Gemini CLI, Cursor, Claude Desktop: whichever are installed
```

`revcenter login` offers to run `revcenter setup` for you. The server uses the key the login saved, so no key
goes in a config file. To add it by hand instead:

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add -s user revcenter -- revcenter mcp
    ```
  </Tab>
  <Tab title="Codex">
    ```bash
    codex mcp add revcenter -- revcenter mcp
    ```
  </Tab>
  <Tab title="Gemini CLI">
    ```bash
    gemini mcp add -s user revcenter revcenter mcp
    ```
  </Tab>
  <Tab title="Cursor, Claude Desktop, others">
    ```json
    { "mcpServers": { "revcenter": { "command": "npx", "args": ["-y", "revcenter", "mcp"] } } }
    ```
  </Tab>
</Tabs>

On a server or in CI, set `REVCENTER_API_KEY` in the client's environment instead of logging in. Restart the
client, then ask it to "list my Revcenter projects".

## Several searches at once

There's no cap on searches running at once: only your credits. Ask the agent to run one sub-agent per role, and
each launches its own search; a burst that finds Revcenter briefly busy is retried for you. When they finish,
`export_shortlist` and `export_candidates` save CSVs (every profile field, plus the profile as JSON) under
`./revcenter-exports/`, `export_search_records` and `export_project_records` save everyone a search or a whole project returned, read or not, ready for the agent to merge, filter or send on.
Every export tool takes `format`: `csv` (the default) for a spreadsheet, or `jsonl` for JSON Lines. For an AI
agent, JSONL is lossless; CSV is for spreadsheets. Out of credits, `create_top_up` opens
Stripe checkout in your browser.

## Results without an agent running

`create_webhook` adds an endpoint of yours that receives `search.completed`, `shortlist.changed` and the rest as
signed POSTs, so a search launched by an agent reaches your ATS or pipeline after the agent has gone. See
[Webhooks](/guides/webhooks).

Every tool returns `structuredContent`: `status` (`ok` or `pending_approval`), `data`, and on lists `cursor` and
`total`. Errors return the [error code](/guides/errors), a one-line fix and the `request_id`.

## Approval before reserving credits

`launch_search` (unless `database_only`) and `expand_search` ask first:

1. The server previews the action: what it does, the credits it reserves, and credits left.
2. If the client supports MCP elicitation, it asks you in one sentence, with Accept and Decline and nothing to
   fill in: `Launch search "Associate · Paul Weiss · New York": reserves up to 1,000 credits, unused credits are
   refunded. 421,000 credits left.` Accept runs exactly what was previewed; Decline (or closing the prompt) runs
   nothing.
3. Otherwise, or if you don't answer within 10 minutes, the tool returns `status: "pending_approval"` with a
   `proposal`. Nothing has run. The agent shows it to you and calls `apply_proposal` after you agree. A
   proposal lasts 30 minutes.

Criteria are reviewed before they run, wherever they come from: a requirement sentence in `must_have` is
scored as context instead of matched as literal text (`review.changes` says so), and a place wider than the
role's own (all of the United States for a role in Mount Jackson, VA) comes back in `review.warnings`. The
prompt shows each warning on its own line, starting `Check:`, so you see it before you accept.

Approvals that arrive together are asked once. When an agent launches several searches in parallel, or
several subagents launch at the same moment, you get one prompt that lists every search and the total it
reserves; one Accept launches them all side by side, one Decline runs none. Anything that arrives while that
prompt is open is asked next, together. For a batch the agent has already drafted, `launch_searches` takes up
to 25 launches in one call and returns each one's outcome: `launched` (with its search), `declined`,
`pending_approval` (with its `proposal_id`) or `failed` (with the error; the others still run).

A launch without its own `idempotency_key` gets one derived from the project and the request, so an agent that
repeats an identical launch (after its tool call timed out, say) gets the first search back. It isn't asked
again and nothing more is reserved.

`max_credits` is at least 250: a smaller cap can't buy one page of results and read the profiles on it.

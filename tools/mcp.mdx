`revcenter mcp` runs a local MCP server. Your agent does the reasoning; Revcenter searches, scores and keeps the
shortlist.

## Connect

The quickest way: paste this into Claude Code, Codex, Cursor or any coding agent.

```text
Set up the Revcenter plugin by following the steps in https://github.com/revcenter/agent-plugins
```

The agent installs the CLI, signs you in (you click **Authorize** once in your browser), connects itself and
tells you how many credits you have. In Claude Code you can also install the plugin directly:

```text
/plugin marketplace add revcenter/agent-plugins
/plugin install revcenter@revcenter-plugins
```

Or do it yourself: install, sign in, and let the CLI add the server to every AI tool on the machine:

```bash
curl -fsSL https://revcenter.ai/install.sh | sh
revcenter login
revcenter setup        # Claude Code, Codex, Gemini CLI, Cursor, Claude Desktop: whichever are installed
```

`revcenter login` offers to run `revcenter setup` for you. The server uses the key the login saved, so no key
goes in a config file. To add it by hand instead:

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add -s user revcenter -- revcenter mcp
    ```
  </Tab>
  <Tab title="Codex">
    ```bash
    codex mcp add revcenter -- revcenter mcp
    ```
  </Tab>
  <Tab title="Gemini CLI">
    ```bash
    gemini mcp add -s user revcenter revcenter mcp
    ```
  </Tab>
  <Tab title="Cursor, Claude Desktop, others">
    ```json
    { "mcpServers": { "revcenter": { "command": "npx", "args": ["-y", "revcenter", "mcp"] } } }
    ```
  </Tab>
</Tabs>

On a server or in CI, set `REVCENTER_API_KEY` in the client's environment instead of logging in. Restart the
client, then ask it to "list my Revcenter projects".

## Several searches at once

There's no cap on searches running at once: only your credits. Ask the agent to run one sub-agent per role, and
each launches its own search; a burst that finds Revcenter briefly busy is retried for you. When they finish,
`export_shortlist` and `export_candidates` save CSVs (every profile field, plus the profile as JSON) under
`./revcenter-exports/`, `export_search_records` and `export_project_records` save everyone a search or a whole project returned, read or not, ready for the agent to merge, filter or send on. Out of credits, `create_top_up` opens
Stripe checkout in your browser.

## Results without an agent running

`create_webhook` adds an endpoint of yours that receives `search.completed`, `shortlist.changed` and the rest as
signed POSTs, so a search launched by an agent reaches your ATS or pipeline after the agent has gone. See
[Webhooks](/guides/webhooks).

## Tools

| Tool | What it does | Cost |
| --- | --- | --- |
| `get_me` | The key's workspace, name, scopes and expiry, the workspace's plan and limits, and today's usage. | Does not use shortlist credits. |
| `get_usage` | Today's requests and searches, and shortlist credits remaining. | Does not use shortlist credits. |
| `get_capacity` | How busy Revcenter is right now: searches running and waiting across the platform and in this workspace, and about when a search launched now would start. | Does not use shortlist credits. |
| `list_actions` | Every action this API offers, with its route, scope and cost class: the catalog the MCP tools are built from. | Does not use shortlist credits. |
| `preview_action` | What an action would do and spend, without doing it; returns a proposal_id that apply_proposal runs within 30 minutes. | Does not use shortlist credits. |
| `apply_proposal` | Run an action previewed with preview_action, exactly as previewed. Applying the same proposal twice returns the first result. | Uses what its preview stated: 1 shortlist credit for a search or an expansion, nothing for anything else. |
| `get_criteria_reference` | Every criteria field, whether it filters LinkedIn before anything is bought or scores after, its allowed values, and an example. Read it before launch_search. | Does not use shortlist credits. |
| `search_industries` | LinkedIn industries matching a word, with their ids; use the labels in current_industries and exclude_industries. | Does not use shortlist credits. |
| `list_projects` | The workspace's projects, newest first, with how many searches each ran and how many are on its shortlist. | Does not use shortlist credits. |
| `create_project` | Make a project: one role, one shortlist. | Does not use shortlist credits. |
| `get_project` | One project, with its search and shortlist counts. | Does not use shortlist credits. |
| `list_searches` | The searches a project has run, oldest first. | Does not use shortlist credits. |
| `launch_search` | Start a LinkedIn search in a project, on `criteria` run exactly as sent, or on a `jd_text` Revcenter reads; with database_only it scores the workspace's candidates on file and uses no credit. | Uses 1 shortlist credit. |
| `get_search` | A search's status, stage, outcome (Shortlist ready, Poor yield, No results) and how many profiles it read; poll until status is no longer queued or running. | Does not use shortlist credits. |
| `cancel_search` | Stop a running search: it buys nothing more, scores what it already read, and keeps them. | Does not use shortlist credits. |
| `list_people` | Everyone a search scored, best first: score, fit readings, signals, whether they are on the shortlist, and the whole read profile. | Does not use shortlist credits. |
| `list_search_records` | Every person a search's result pages listed, read or not, in the order returned: each with what became of them (`scored`, `known`, `not_read`), the score if scored, and the read profile when your workspace holds one. | Does not use shortlist credits. |
| `export_search_records` | Every record a search returned as CSV, saved to a file (default `./revcenter-exports/<search_id>-records.csv`): one row per person, read profiles as text columns. | Does not use shortlist credits. |
| `list_project_records` | Every person any of a project's searches returned, expansions included, once each: status rolled up across the searches, the best score, `first_search_id` and `search_ids`, and the read profile when your workspace holds one. | Does not use shortlist credits. |
| `export_project_records` | Every record a project's searches returned as CSV, saved to a file (default `./revcenter-exports/<project_id>-records.csv`), with `first_search_id` and `search_ids` (joined by `;`). | Does not use shortlist credits. |
| `preview_scoring` | What a cut-off, weight or requirement change would do to the shortlist, before and after; changes nothing. | Re-scores the people already found. Does not use shortlist credits. |
| `apply_scoring` | Apply a cut-off, weight or requirement change: everyone already read is re-scored and the shortlist moves. | Re-scores the people already found. Does not use shortlist credits. |
| `run_database_pass` | Score the workspace's candidates on file against this search; those who clear the bar join the shortlist. | Re-scores the people already found. Does not use shortlist credits. |
| `expand_search` | A live LinkedIn pass for more people on the same role, skipping everyone already found; at most 2 per project. | Uses 1 shortlist credit. |
| `export_shortlist` | The shortlist as CSV, saved to a file (default `./revcenter-exports/shortlist-<project>.csv`): every profile field, the profile as JSON last. | Does not use shortlist credits. |
| `get_shortlist` | Everyone on the project's live shortlist, best first, with full profiles. | Does not use shortlist credits. |
| `add_shortlist_members` | Put people the project's searches found on its shortlist, by candidate id (from list_people). | Does not use shortlist credits. |
| `remove_shortlist_member` | Take someone off the shortlist, with an optional reason. | Does not use shortlist credits. |
| `wait_for_search` | Wait until a search finishes (or the timeout passes), checking every 10 seconds (up to a minute while it waits far back in line), and return its final status. | Does not use shortlist credits. |
| `list_candidates` | Everyone any of this workspace's searches found, newest first, as the Candidates tab lists them; filter by text, project, title, company or place. | Does not use shortlist credits. |
| `export_candidates` | The candidate database as CSV, saved to a file (default `./revcenter-exports/candidates.csv`): every profile field, the profile as JSON last. | Does not use shortlist credits. |
| `create_top_up` | A Stripe checkout link to add shortlist credits at the plan's rate, opened in your browser; nothing is charged until someone pays. | Does not use shortlist credits. |
| `list_webhooks` | Your [webhook](/guides/webhooks) endpoints: URL, events, whether each is on. Never the secret. | Does not use shortlist credits. |
| `create_webhook` | Add an HTTPS endpoint that receives search and shortlist events as signed POSTs; returns the signing secret once. | Does not use shortlist credits. |
| `update_webhook` | Change an endpoint's URL, events or description, or turn it off and on. | Does not use shortlist credits. |
| `delete_webhook` | Remove an endpoint and its delivery history. | Does not use shortlist credits. |
| `test_webhook` | Send a signed `webhook.test` event now and return the status code the endpoint answered. | Does not use shortlist credits. |
| `list_webhook_deliveries` | What was sent to an endpoint, newest first: status, attempts, response code, next retry. | Does not use shortlist credits. |
| `redeliver_webhook` | Send a delivery's event again, with the same event id. | Does not use shortlist credits. |

Every tool returns `structuredContent`: `status` (`ok` or `pending_approval`), `data`, and on lists `cursor` and
`total`. Errors return the [error code](/guides/errors), a one-line fix and the `request_id`.

## Approval before using a credit

`launch_search` (unless `database_only`) and `expand_search` ask first:

1. The server previews the action: what it does, its cost, and credits left.
2. If the client supports MCP elicitation, it asks you. Yes runs exactly what was previewed.
3. Otherwise the tool returns `status: "pending_approval"` with a `proposal`. Nothing has run. The agent shows
   it to you and calls `apply_proposal` after you agree. A proposal lasts 30 minutes.
